## 1. 目的与适用范围

### 1.1 目的

本规范规定「萌萌识字」产品在 **UniApp + Vue** 技术栈下的专属开发规则，确保：

1. 代码结构、命名与数据口径在全项目内一致；
2. 业务逻辑与 UI 解耦，便于低龄识字、拼音点读、课内同步等模块独立演进；
3. 源程序具备可识别、可审查的原创特征，支撑软件著作权登记与后续维护。

### 1.2 适用范围

适用于本仓库全部源程序与配套文档，包括但不限于：

- 客户端页面与组件（`pages/`、`components/`）
- 业务模块与用例（`modules/`）
- 服务、仓储、状态（`services/`、`repositories/`、`store/`）
- 工具与常量（`utils/`、`constants/`、`data/`）
- 静态资源与构建脚本（`static/`、`scripts/`）
- 单元测试（`tests/`）

### 1.3 术语

| 术语 | 含义 |
|------|------|
| **MM-5L** | 萌萌识字五层工程模型（见 §2） |
| **域（domain）** | 与产品 Tab 或业务线对应的代码分区，如 `literacy`、`pinyin` |
| **用例（usecase）** | `modules/{域}/usecases/` 下单一入口函数，编排页面跳转或业务流程 |
| **仓储（repository）** | 唯一允许读写持久化数据的模块层 |
| **Lab** | 拼音实验室子产品，含 `initial-lab`、`vowel-lab`、`tone-lab`、`whole-lab` |

## 2. MM-5L 工程分层模型（原创架构约束）

萌萌识字采用 **MM-5L** 五层分离，**禁止跨层越权调用**。

```
┌─────────────────────────────────────────┐
│  L1 · 表现层    pages/  components/      │
├─────────────────────────────────────────┤
│  L2 · 应用层    modules/*/usecases/     │
├─────────────────────────────────────────┤
│  L3 · 领域层    services/  data/  rules  │
├─────────────────────────────────────────┤
│  L4 · 数据层    repositories/  store/   │
├─────────────────────────────────────────┤
│  L5 · 基础设施  utils/  static/  config/ │
└─────────────────────────────────────────┘
```

### 2.1 各层职责

| 层级 | 目录 | 允许 | 禁止 |
|------|------|------|------|
| **L1 表现层** | `pages/`、`components/` | 渲染 UI、绑定事件、调用 store 只读 getter、调用 usecase | 直接 `uni.setStorageSync`；直接拼装选题/支付/进度算法 |
| **L2 应用层** | `modules/*/usecases/` | 编排跳转、组合多个 service/repository 调用 | 操作 DOM；内嵌大段 UI 字符串模板 |
| **L3 领域层** | `services/`、`data/` | 业务规则、报告生成、会员配额、推荐选题 | 依赖具体 `.vue` 文件 |
| **L4 数据层** | `repositories/`、`store/` | 读写 Storage、seed JSON、内存缓存；store 聚合刷新 | 页面路由；复杂 UI 文案 |
| **L5 基础设施** | `utils/`、`config/`、`static/` | 纯函数、音频、字体、平台适配 | 引用 pages；写入用户进度 |

### 2.2 依赖方向（强制）

```
L1 → L2 → L3 → L4 → L5
```

- **允许**：上层调用下层；同层模块通过明确 export 互相调用。
- **禁止**：下层 import 上层（例如 `utils/` 不得 import `pages/`）；`repositories/` 不得 import `components/`。

### 2.3 全局 Store 划分

与 `store/index.js` 初始化顺序一致，全局状态仅拆为四类，**不得新增裸全局变量文件**：

| Store 文件 | 职责 |
|------------|------|
| `app-store.js` | 启动就绪、主题、版本、权限态 |
| `curriculum-store.js` | 当前教材版本、年级、学期、字表偏好 |
| `learning-store.js` | 识字/拼音进度聚合、今日任务摘要 |
| `user-store.js` | 用户信息、勋章、家长设置 |

页面 **只读** store；写入必须经 **repository** 或 **service** 完成后再 `refresh*State()`。

## 3. 命名与文件组织

命名细则以 **`docs/命名规格.md`** 为附件 A，本节仅列 **著作权语境下的强制条款**（体现本产品原创工程特征）。

### 3.1 专属前缀体系

| 前缀 | 用途 | 示例 |
|------|------|------|
| `meng-` | 萌萌品牌壳层 UI（导航、状态栏、广告位） | `meng-page-nav.vue` |
| `pinyin-` | 拼音域 UI 与四线格等 | `pinyin-four-lines-row.vue` |
| `*-lab` | 拼音实验室路由与工具目录 | `pages/pinyin/tone-lab/` |
| `vip-` | 会员、配额、支付 | `vip-quota.js` |
| `renjiao` / `curriculum` | 统编教材与生字 seed | `renjiao-textbook-loader.js` |

### 3.2 文件命名铁律

1. 源文件（除 `static/pinyin/` 音频外）一律 **kebab-case**。
2. 服务、仓储、状态文件必须带后缀：`*-service.js`、`*-repository.js`、`*-store.js`。
3. 用例文件：`{动词}-{名词}.js`，导出同名 camelCase 函数，如 `start-literacy-game.js` → `startLiteracyGame()`。
4. 测试文件：`tests/{特性}.test.mjs`。

### 3.3 标识符铁律

| 场景 | 风格 |
|------|------|
| 函数、变量、Vue data/computed/methods | camelCase |
| 导出常量、Storage 键名常量 | UPPER_SNAKE_CASE |
| JSON / Storage 持久化字段 | snake_case |
| CSS 类名 | kebab-case，带域前缀 |

新增或大幅改写的 **`.js` / `.vue` / `.mjs`** 文件，须在文件首部添加统一注释块，便于著作权源程序鉴别与维护归属。

```javascript

 * @file start-literacy-game.js
 * @module modules/literacy/usecases
 * @description 趣味识字营入口：导航至游戏页
```

```vue
<!--
  @file meng-page-nav.vue
  @layer L1 表现层
  @description 萌萌识字统一页头导航
```

## 5. Vue 页面与组件规范

### 5.1 页面（L1）

1. 路由注册仅通过 **`pages.json`**，path 与磁盘路径严格一致。
2. 页面 `.vue` 中 **script 逻辑上限**：生命周期钩子 + 事件转发 + store 映射；超过 80 行业务逻辑须下沉至 `modules/` 或 `services/`。
3. 路由跳转：**用户主动入口** 优先经 `modules/*/usecases`；页内子步骤可用 `uni.navigateTo`，但不得散落重复 URL 字符串——相同目标须提取到 usecase 或 `constants/` 路由表。
4. 自定义导航栏页面须使用 **`meng-page-nav`** 或 **`meng-sub-page`** 壳组件，保持全站一致。

### 5.2 组件（L1）

1. 全局注册组件仅限 **`main.js`** 中声明的极少数壳组件（如 `MengStatusBarSpacer`）；其余通过 easycom 或局部 import。
2. Props 必须声明类型与默认值；事件名使用 kebab-case。
3. 组件不得直接调用 `services/vip-pay-service.js` 等支付接口，须经页面或 usecase 授权。

### 5.3 样式

1. 全站主题与页壳：`static/styles/app-theme.css`、`meng-page.css`。
2. 拼音专用字体与四线格：`static/styles/pinyin-font.css`；页面内不得硬编码字体路径。
3. 新增页面根 class 与路由语义一致，如 `.lesson-dictation`、`.pinyin-tone-lab`。

## 6. 数据与持久化规范

### 6.1 Schema 单一事实来源

字段定义、Storage 键、教材版本枚举 **以 `constants/curriculum-schema.js` 为准**。变更须同步：

- `docs/sqlite-schema.md`
- 相关 `*-storage.js` / `build-db.mjs`
- 本规范修订记录

### 6.2 进度布尔与时间

| 字段 | 规则 |
|------|------|
| `learned`、`mastered` 等 | Storage 内 **0 / 1**，禁止混用 `true/false` 字符串 |
| `updated_at_ms` | Unix 毫秒整数 |
| `semester` | 中文 **`上` / `下`**，与 `SEMESTER` 常量一致 |
| `textbook_version_id` | 中文显示名，如 `统编(人教版)` |

### 6.3 Storage 键版本策略

- 格式：`{语义}_v{N}`，snake_case。
- 结构不兼容时 **新增键**，在读写层做一次性迁移；禁止覆写旧键语义。
- 键名常量集中声明：优先 `STORAGE_KEYS`；域内专用键放在对应 `utils/*/constants.js`。

### 6.4 教材生字数据流

```
scripts/seed-curriculum.json
        ↓ npm run db:build
constants/hanzi_curriculum_seed.json
        ↓ curriculum-db.js 查询
应用层展示与进度关联
```

- 课内 JSON 文件名 **禁止手写**，须调用 `renjiaoTextbookJsonFile()`（`constants/renjiao-textbook-filenames.js`）。
- 展示顺序：`sort_order ASC, id ASC`（与 `queryCurriculumChars` 一致）。

## 7. 拼音点读与音频规范（本产品核心原创约束）

### 7.1 播放会话 API

拼音本地播放统一经 **`utils/pinyin-play-session.js`** 及 **`PINYIN_PLAY_SCOPES`**，详见 `docs/拼音点读-播放会话API.md`。

| 规则 | 说明 |
|------|------|
| 作用域 | 乐园/闯关用 `GLOBAL`；课卡、小测、查字等用独立 scope |
| 世代取消 | 播放前 `begin()`，离开页面或新播放须 `cancel()`；异步回调内用 `isStale(gen)` 丢弃过期结果 |
| 禁止 | 页面内直接 `new InnerAudioContext` 播放拼音；绕过 scope 并发播放 |

### 7.2 页面集成

拼音相关页面通过 **`mixins/pinyin-play-scope.js`** 挂载 `this._pyPlay`，与 scope 常量一致。

### 7.3 静态音频资源

| 目录 | 命名 |
|------|------|
| `static/pinyin/` | 带声调拼音 + `.opus` |
| `static/voice/mengmeng/` | `{场景}_{结果}.opus`，snake_case 英文 |
| 播放封装 | `utils/play-pinyin-local-audio.js`、`utils/safe-inner-audio-play.js` |

## 8. 识字与拼音 Lab 业务规范

### 8.1 识字闭环

标准路径（代码命名须能对应此链路）：

```
home → textbook/lesson → char 学习 → quiz/dictation → repository 写入 → learning-store 刷新
```

- 错题：`wrong_count` 递增，由 `repositories/learning-repository.js` 记录。
- 每日一练选题：`services/daily-training-service.js`、`services/recommend-service.js`，页面不得硬编码字表。

### 8.2 拼音 Lab 子域

四类 Lab 目录名固定，不得新增 fifth-lab 类命名：

- `initial-lab`（声母）
- `vowel-lab`（韵母）
- `tone-lab`（声调）
- `whole-lab`（整体认读）

子页短名固定集合：`index`、`ear`、`mouth`、`group`、`chart`、`match`、`body`、`mark`、`tip`（按 Lab 选用，不发明同义新名如 `listen` 代替 `ear`）。

Lab 进度 Storage 独立键，如 `vowel_lab_progress_v1`，读写仅在对应 `utils/pinyin-*-lab/progress.js`。

### 9.1 配置分离

- 支付与 API：`config/vip-pay-config.js`
- 商品定义：`constants/vip-products.js`

3. 广告位 ID 仅定义于 `constants/ad-placements.js`、`config/ad-config.js`。

## 10. 安全、隐私与合规

1. **最小存储**：用户进度、偏好存本地 `uni.storage`；不上传字段须在产品隐私政策中声明。
2. **家长验证**：涉及设置变更、支付、数据清除的入口须经 `pages/settings/guardian.vue` 或等效门控。
3. **调试能力**：`pages/debug/`、`utils/debug-console-hook.js` 仅开发构建可用，发布包须可关闭或不可达。
4. **密钥**：API 地址、广告 ID 等放 `config/`，禁止提交真实生产密钥至公开仓库；登记版源程序可脱敏占位。
5. **第三方库**：`cnchar` 系列等依赖遵守其开源协议；本项目 **组合方式、封装层与业务数据** 仍属本软件著作权范围。
